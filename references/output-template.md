# 发芽报告输出模板

## 用途

定义发芽报告的标准 Markdown 结构。Skill 执行时按此模板填充内容。

> **两层模式（无笔记库）**：用户直接粘贴内容、没有可搜索的笔记库时，省略「🔗 本地笔记的洞察」整章，发芽建议全部基于外部发现与拷问。

---

## 文件头部

```markdown
---
id: {原笔记id}
source_note: "[[YYYYMMDD-主题]]"
generated_at: YYYY-MM-DD HH:MM
sprout_version: v2.0
status: draft
---
```

> **注**：若执行了发芽标记，`source_note` 中的链接会随全库 wikilink 同步自动更新为带 🌱 的新文件名。

## 本地笔记的洞察写作规范

### 结构要求

- 章节标题用「🔗 本地笔记的洞察」(H2)
- 下面先用 1-2 段总述（点出整体 pattern），**总述直接挂在 H2 下，不加任何子标题**——凡基于库内笔记的判断都是本地洞察，不要发明「关联网络洞察」之类的中间层标题
- 总述段落后可附「📎 佐证来源」引用块：引用了新闻稿/公开课/文章的判断，附上可追溯的 URL（方便用户追溯）
- 再写「### 一 / 二 / 三...」(H3) 做具体洞察，直接挂在「本地笔记的洞察」(H2) 下
- **不要用表格**，用叙述性文字，像写"跨领域故事"那样把关联讲清楚

### 每条洞察的必备要素

1. **一句话结论**：标题直接点出这条洞察的核心发现
2. **叙述性展开**：说明这些笔记之间到底有什么关系、放在一起碰撞出什么新洞察
3. **原文链接**：每条洞察末尾用「——原文：[[笔记名]]」附上分析所依据的原文链接（可多个，让用户能点回去对照原始笔记）

### 写作原则

- 不只是列链接，要写出**为什么它们有关联**
- 要解释"这张笔记和那篇笔记放在一起，会产生什么化学反应"
- 关联洞察总述是重点——这是 AI 帮你**看见你自己知识库里隐含的 pattern**
- 每条具体洞察都附上原文链接，把"洞察结论"和"证据原文"绑定

## 发芽故事写作规范

### 每个故事的必备要素

1. **🌱 种子引子**：明确说明"因为笔记中提到了XX，这让我想到YY"，建立联想链条
2. **完整故事展开**：
   - **背景**：时间、地点、人物、当时的处境
   - **冲突**：遇到了什么困难/危机/矛盾
   - **行动**：采取了什么行动（重点描写）
   - **结果**：最终发生了什么
   - **洞察**：从结果中提炼的深层道理
3. **✨ Aha 瞬间**：
   - 不是引用别人的话
   - 是从刚刚讲完的故事中**自己提炼**的洞察
   - 格式：用引号包裹，像一句可以被带走的话
   - 句式建议："真正的XX，不是YY，而是ZZ" / "XX的陷阱在于，你以为是YY，其实是ZZ"
4. **📎 参考文档链接**（必填，硬要求）：在 Aha 瞬间之后，用引用块列出本故事所依据的可追溯来源（权威文章/原始案例/公开课/词条等），每条附可点击 URL。网络洞察的本质是"从外部找多视角印证"，可追溯是硬要求；若故事是改编自某经典案例，链接里注明原始出处。

### 层级与命名

- 所有跨领域故事都挂在 `## 🌐 网络洞察`(H2) 这个二级目录下
- 每个故事用 `### 一、二、三…`(H3) 做标题，直接挂在「网络洞察」下
- 命名用中文数字「一、二、三」，与本地笔记洞察的「一、二、三」保持统一

### 故事选择标准

| 优先级 | 标准 | 说明 |
|--------|------|------|
| P0 | 跨领域 | 与笔记原领域差异越大，冲击力越强 |
| P0 | 有真实人物 | 具体的人比抽象的概念更有感染力 |
| P1 | 有具体数据/时间 | 1970年4月13日，比"很久以前"更有说服力 |
| P1 | 有反转/意外 | 结局出乎意料的故事更容易触发 Aha |
| P2 | 与笔记核心概念直接相关 | 联想链条要清晰，不能牵强 |

### 故事串联原则

- 故事之间不要孤立，后面的故事可以回应前面的洞察
- 可以用"但这还不是全部"、"更深层的问题是"等过渡句串联
- 最后一个故事最好回到用户自身，让洞察可迁移

## 拷问写作规范

### 语气

- 像真人在对话，不是机器在提问
- 可以用反问句、排比句增加力度
- 适当使用"说实话"、"其实"、"但问题是"等口语化衔接
- **不要表格，不要分点，要像一段连续的对话**

### 必覆盖的维度（至少 3-4 个）

1. **逻辑谬误**："这个判断有个偷换概念的地方" / "你把两个不冲突的东西对立起来了"
2. **前提追问**："这个判断的前提是XX，但如果前提不成立呢？"
3. **代价计算**："你只算了A账，没算B账"
4. **概念澄清**："你说的'XX'，到底是A还是B？这两个是不一样的"
5. **边界追问**："这个结论在什么情况下不成立？"
6. **动机追问**："你真正佩服的是A，还是B？这两个是不一样的"

### 结构

```
你这条笔记的核心判断是——"..."

这个判断有个问题：...（直接指出逻辑谬误）

还有，...（追问前提/代价/概念澄清）

...（继续追问，层层递进）

最后问你一个：...（动机追问，逼到墙角）

所以真正的问题是：...（一句话总结）
```

## 发芽建议规范

- 不是泛泛的"多看看"，而是基于本次发芽的**具体发现**
- 每条建议对应前面的某个故事洞察、拷问追问或本地笔记的洞察
- 用 `[ ]` 复选框格式，方便用户完成后打勾
- 建议数量：2-3 条，不要太多

## 质量检查清单

生成报告后自检：
- [ ] 种子摘要控制在 2-3 句话内
- [ ] 本地笔记的洞察章节：H2 下直接是总述段落（无「关联网络洞察」子标题）+ 至少 2 条具体洞察（### 级别，命名为「一、二、三…」），每条附原文链接；总述引用了外部公开记录的附「📎 佐证来源」链接，无表格
- [ ] 网络洞察章节：有 `## 🌐 网络洞察`(H2) 二级目录，下面至少 3 个 `### 一/二/三`(H3) 故事，每个 Aha 瞬间后都附 📎 参考文档链接（可追溯 URL）
- [ ] Aha 瞬间是从故事中自己提炼的，不是引用别人的
- [ ] 拷问是直接对话式，不是表格，至少覆盖了 3-4 个维度
- [ ] 拷问最后有动机追问
- [ ] 发芽建议 2-3 条，每条对应前面的具体发现
- [ ] 没有修改原笔记正文主体内容

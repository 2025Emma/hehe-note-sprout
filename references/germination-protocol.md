# 发芽协议 (Germination Protocol)

## 协议版本

v2.0 — 对应 hehe-note-sprout SKILL.md（公开版）

---

## 第一层：本地发芽协议

### 种子关键词提取规则

1. **标题关键词**：去掉 `YYYYMMDD-` 前缀（如有），剩余部分按空格/标点分词
2. **Tags**：直接取 frontmatter 中的 `tags` 列表
3. **Wikilinks**：提取正文中所有 `[[...]]` 的目标名称
4. **全文关键词**：
   - 提取所有名词、名词短语（2-4 字优先）
   - 排除停用词（的、了、是、在、和、或等）
   - 按出现频率 + 在标题/首段的位置加权
   - 最终取 5-10 个，按重要性排序

### 搜索优先级

执行顺序：
1. 已有连接反向搜索（最高权重）
2. 标签匹配（高权重）
3. 标题匹配（高权重）
4. 全文关键词匹配（中权重，限制返回 Top 20）

### 关联度排序规则

1. **已有双向 wikilink** > **单向被引用** > **标签匹配** > **标题匹配** > **正文关键词匹配**
2. 同目录（与原笔记同目录）优先 +1 级
3. 排除：自身与配置中的排除目录（默认 `.obsidian`、`.trash`、`.git`、`node_modules`）
4. 最终输出：Top 5-8 张最相关的本地笔记

### 关联摘要格式

对每张关联笔记提取：
- `文件名`：显示为 wikilink `[[文件名]]`
- `标题`：笔记的 H1 标题
- `核心观点`：1-2 句话概括
- `关联理由`：为什么与当前笔记相关

> **注意**：本地发芽的发现写入发芽报告的「🔗 本地笔记的洞察」章节；若用户授权了发芽标记，「已有连接 + 建议新连接」的快捷链接同时写入原文末尾的「🌱 发芽」区块。

## 第二层：外部发芽协议

### 查询构建规则

**同领域查询**：
- 从种子关键词中选 1-2 个最核心的概念
- 按笔记类型套用查询模板
- 每个核心概念执行 1 次搜索

**跨领域查询**：
- 分析笔记内容涉及的主题，判断可能关联的跨领域
- 常见跨领域映射：
  - 技术/产品 → 心理学（用户行为）、经济学（激励机制）、传播学（信息扩散）
  - 电影/作品 → 工程学（项目管理）、社会学（群体心理）、历史学（时代背景）
  - 个人成长 → 神经科学（习惯形成）、组织行为学（团队协作）、哲学（存在主义）
- 构建查询：`{主题} {跨领域} 视角 / 解读 / 应用`
- 执行 1 次搜索

### 来源过滤标准

**优先采纳**：
- 学术期刊、大学官网、研究机构
- 权威媒体（如财新、第一财经、36氪、澎湃新闻等中文媒体，或对应语种的权威媒体）
- 知名作者专栏/博客（有明确作者身份）
- 有专业背书的课程平台、知乎高赞回答

**排除**：
- 内容农场、聚合站、无明确作者的转载
- 匿名论坛
- 过于陈旧的信息（超过 5 年且非经典文献）

### 视角分类标准

| 分类 | 判定标准 |
|------|---------|
| 同领域支持 | 与笔记核心观点一致，或提供补充证据 |
| 同领域反对/质疑 | 与笔记核心观点冲突，提出反面论据 |
| 跨领域延伸 | 从不同学科/行业角度解读同一主题 |
| 方法论迁移 | 其他领域的方法/框架能否应用到此主题 |

## 第三层：专家拷问协议

### 镜片选择规则

默认使用：**段永平式（本质维度）+ 快刀青衣式（落地维度）**

笔记明显属于某类型时，按 `expert-lens-registry.md` 的选择矩阵换用对应组合：

| 笔记类型 | 挑战视角 A（本质） | 挑战视角 B（落地） |
|---------|-------------------|-------------------|
| 通用观点/思考 | 段永平式 | 快刀青衣式 |
| AI/技术相关 | Karpathy 式 | 段永平式 |
| 产品/内容创作 | 乔布斯式 | 段永平式 |
| 商业/投资 | 段永平式 | 快刀青衣式 |
| 个人成长/学习 | 罗振宇式 | 段永平式 |

拷问时使用"某某式判断框架"，是基于公开资料萃取的视角，不得声称专家本人在场。

### 问题输出格式

每个镜片输出 3-4 个问题，每个问题必须包含：
1. **挑战问题**：具体、可回答的问题
2. **为什么问**：这个问题击中了笔记的哪个薄弱点
3. **思考角度**：用这个镜片的哪个核心框架来回答
4. **可能的答案方向**：不是给标准答案，而是提示思考路径

### Top 3 问题汇总规则

从两个镜片的 6-8 个问题中，选出最值得验证的 Top 3：
1. 选择「如果回答不出来，笔记就站不住脚」的问题
2. 优先选择跨镜片的问题（即两个视角都指向的薄弱点）
3. 标注验证方式：查资料 / 问专家 / 自己实践

## 报告生成协议

### 报告逻辑（阅读顺序）

发芽报告按「**先快速回顾你在说什么，再看你的知识库里还藏着什么关联，然后用故事帮你看见更大的世界，最后逼你想深一层**」的逻辑排布：

1. **种子摘要**（概要）——先快速回顾原笔记的核心判断，确认地基
2. **本地笔记的洞察**（关联）——凡基于库内笔记的判断都是本地洞察；H2 下直接写总述段落（可附「📎 佐证来源」外部链接），每条洞察附原文链接
3. **网络洞察**（扩展）——3-5 个跨领域故事，统一挂在 `## 🌐 网络洞察`(H2) 二级目录下，每个故事用 `### 一 / 二 / 三`(H3) 三级目录；有种子引子 + 完整展开 + Aha 瞬间，**Aha 之后必须附「📎 参考文档链接」（可追溯 URL）**
4. **专家拷问**（挑战）——对话式拆解，直接指出逻辑漏洞
5. **发芽建议**（行动）——把上述发现转化为可执行的下一步动作

> **本地笔记的洞察结构**：
> - H2 下直接用 1-2 段总述（点出整体 pattern），**不加「关联网络洞察」等中间层子标题**——凡基于库内笔记的判断都是本地洞察
> - 总述后可用引用块附「📎 佐证来源」：引用了新闻稿/公开课/文章的判断都要附可追溯 URL
> - `### 一 / 二 / 三...`(H3) 做具体洞察，直接挂在 `## 🔗 本地笔记的洞察` 下
> - 不用表格，用叙述性文字；每条洞察末尾附「——原文：[[笔记名]]」

### 文件位置

发芽报告默认生成在**原笔记所在目录**（与笔记放一起）：

- 路径：`{原笔记所在目录}/{YYYYMMDD}-{主题}-发芽报告.md`
- `YYYYMMDD`：生成日期
- `{主题}`：原笔记标题去掉日期前缀（如有）后的主题名
- 用户想统一存放时，按用户指定的报告目录输出

### 质量检查清单

生成报告后自检：
- [ ] 种子摘要准确概括原笔记核心判断（2-3 句话）
- [ ] 本地笔记的洞察章节：H2 下直接是总述（无「关联网络洞察」子标题）+ 至少 2 条具体洞察（### 级别，命名为「一、二、三…」），每条附原文链接；总述引用了外部公开记录的附「📎 佐证来源」，无表格
- [ ] 网络洞察章节：有 `## 🌐 网络洞察`(H2) 二级目录，下面至少 3 个 `### 一/二/三`(H3) 故事，每个有种子引子 + 完整展开 + Aha 瞬间，Aha 后附「📎 参考文档链接」（可追溯 URL）
- [ ] 拷问是对话式，至少覆盖 3-4 个维度，最后有动机追问
- [ ] 发芽建议 2-3 条，每条对应前面的具体发现
- [ ] 没有修改原笔记正文主体内容

### 原文末尾「发芽」区块（用户授权发芽标记后）

在原笔记末尾追加：
```markdown
---

## 🌱 发芽

🌱 [[{YYYYMMDD}-{主题}-发芽报告|发芽报告]]

### 相关笔记

**已有连接**
- [[{笔记A}]]
- [[{笔记B}]]

**建议建立的新连接**
- [[{笔记C}]]
```

### 已发芽笔记的标识

- 在原文笔记文件名末尾加 `🌱`
- 同步更新全库中所有引用该笔记的 wikilink
- 示例：`20260827-一次关于产品优先级的争论🌱.md`

## 发芽建议协议

### 什么是发芽建议？

不是泛泛的"多看看"，而是基于本次发芽的具体发现，给出的**可执行下一步动作**。每条建议都应该对应前面某一部分的发现：

| 建议类型 | 对应发现 | 示例 |
|---------|---------|------|
| 补充视角 | 外部视角中的某个观点值得纳入笔记 | 补充「本地媒体的质疑视角」到笔记中 |
| 验证问题 | 专家拷问中的某个问题需要回答 | 验证问题："这个结论的边界在哪里？" |
| 方法论迁移 | 跨领域的方法论可以重构笔记 | 用「项目复盘检查清单」重新组织笔记结构 |
| 升级卡片 | 笔记已足够成熟，可以升级为永久笔记 | 添加 frontmatter tags，整合跨领域视角 |

### 发芽建议的数量

- 最少 2 条，最多 5 条
- 优先选择「现在就能做」的动作，而非「以后有空再做」的宏大计划

## Aha 瞬间协议

### Aha 瞬间的标准

1. **必须自己提炼**：从刚讲完的故事中生长出来，**不是引用别人的金句**
2. **高度相关**：与笔记主题直接相关，能加深对核心判断的理解
3. **简短有力**：适合作为"带走的一句话"，不超过 50 字
4. **优先跨领域**：跳出原领域的洞察更有冲击力

### 推荐句式

- "真正的XX，不是YY，而是ZZ"
- "XX的陷阱在于，你以为是YY，其实是ZZ"

### 数量

- 每个跨领域故事 1 句，紧跟故事之后
- 每句 Aha 之后必须附「📎 参考文档链接」（故事所依据的可追溯来源 URL）
